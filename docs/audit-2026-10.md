# Project Audit — October 2026

> **Date**: 2026-10-03 | **Audited revision**: `e1e4aeb` (2024-12-17) plus the uncommitted changes found at that time | **Method**: static read of the repository, compared with `cyrillrx/coding-conventions`, the two intended consumers and the late-2026 toolchain. Nothing was built; findings marked _likely_ need a Gradle run to confirm.

The repository was left after the Java-to-KMP migration of December 2024. It must now serve several personal projects, each in its own repository. This document records the state it was found in; [`roadmap.md`](roadmap.md) describes how it is brought in line.

## Blockers

- **Broken git index.** The staged copy of `shared/logger/build.gradle.kts` had a stray `f` after `implementation(libs.kotlinx.datetime)` on line 37. The working tree was correct, so committing the index as-is would have broken the build.
- **Nothing is published.** There is no `maven-publish`, no signing, no `group`, no `jitpack.yml`. `.github/workflows/` is empty and therefore not even tracked by git.
- **The satellite modules never compile their code** (_likely_). `logger-crashlytics`, `tracker-firebase`, `tracker-amplitude`, `tracker-segment`, `device` and `notifier` apply only `com.android.library`, with no Kotlin plugin, while all their sources are `.kt` files. Besides:
  - `SegmentTracker` calls `TrackerChild()` without the required name, reads a non-existent `event.customAttributes` and never implements `doTrack`.
  - `HardwareUtils` lives in `com.cyrillrx.android.device` while the namespace is `com.cyrillrx.device`, so `R.bool.is_tablet` cannot resolve.
- **iOS demo.**
  - Two dynamic frameworks, `KMPLogger` and `KMPTracker`, are embedded side by side. Each carries its own Kotlin runtime and its own copy of the logger classes, so types do not match across them.
  - The Release `FRAMEWORK_SEARCH_PATHS` in `project.pbxproj` (lines 354-355) still point at `../logger/...` instead of `../shared/logger/...`.
  - `Info.plist` requires `armv7`.
  - The framework module and the Obj-C class share the name `KMPLogger`.
- **Android demo.** `targetSdk` is never set, so it falls back to `minSdk` (23); there is no `versionCode` or `versionName`.

## Bugs

- `SystemOutLog.kt` (lines 18-19) prints each message twice, the second time as `kotlin.Unit`: the first line stores the result of `.let(::println)` and the second prints it.
- **No thread safety.** `Logger` iterates a plain `HashSet`, `Tracker` a plain `HashMap`. On the JVM, adding a child while another thread logs throws `ConcurrentModificationException` from the loop itself, outside the per-child `try`, so it reaches the caller. On Kotlin/Native these are unsynchronised data races. A child that adds or removes children while being called triggers the same failure on a single thread.
- `Tracker.track` hands every event the same live `TrackerContext`. A later `updateUser()` rewrites the context of events already tracked.
- `TrackEvent.Builder` passes its internal map to the event, so reusing a builder shares the map between events.
- `LogEvent` uses the whole formatted log line, timestamp included, as the event **name**, which breaks Firebase's 40-character limit. Its `screen` parameter is never used.
- `FirebaseTracker` throws on an over-long name, key or value; `Tracker`'s catcher swallows it, so the event is silently dropped.
- `Tracker.clear()` does not call `onTrackerRemoved()`. Adding a child with an existing name silently replaces it.
- `MainActivity` adds `SystemOutLog` and `LogCat` in `onCreate`, with no `Application` class: every Activity recreation adds another pair.
- `:shared:tracker` depends on `:shared:logger` with `implementation` while `LogEvent` exposes `Severity` publicly; it should be `api`. The satellite modules make the same mistake with `TrackerChild` and `LogChild`.
- The iOS exception catcher in `iOSApp.swift` (lines 38-42) ignores the error and passes `throwable: nil`.

## API design and quality

### Public API

- **Logger.** `object Logger` (`@ObjCName("KMPLogger")`), abstract `LogChild` with a protected `shouldLog`, `SeverityLogChild`, `ExceptionCatcher`, `LogHelper`, the `L` typealias, and console children `SystemOutLog`, `LogCat`, `NsLogger`, `OsLogger`.
- **Tracker.** `object Tracker` (`@ObjCName("KMPTracker")`), abstract `TrackerChild` with a public `shouldTrack` and lifecycle callbacks, mutable `open class TrackEvent` with an `Any`-typed attribute map, `LogEvent`, and the context types `TrackerContext`, `TrackingApp`, `TrackingUser`, `TrackingDevice`, `Connectivity`.

### Shortcomings against the market

| Expected feature (Kermit, Timber, Napier, Sentry) | State                                                    |
|---------------------------------------------------|----------------------------------------------------------|
| Lazy message evaluation                           | Missing: `message` is a `String`                         |
| Structured attributes                             | Missing                                                  |
| Injectable instance, fakeable in tests            | Missing: global `object` singletons only                 |
| Thread-safe child registry                        | Missing                                                  |
| Natural severity order                            | Inverted: `FATAL = 0` … `VERBOSE = 5`                    |
| `fatal()` shortcut                                | Missing although `Severity.FATAL` exists                 |
| `os_log` subsystem and category                   | Missing: `OS_LOG_DEFAULT`, tag dropped                   |
| Public `os_log` API                               | No: `_os_log_internal`, borrowed from Kermit             |
| Consent and redaction                             | Missing                                                  |
| Immutable events                                  | No: mutable map, `lateinit var context`, unchecked casts |

### Inconsistencies between the two libraries

| Aspect              | Logger                       | Tracker              |
|---------------------|------------------------------|----------------------|
| Child storage       | Set, by identity             | Map, by name         |
| Reset               | `release()`                  | `clear()`            |
| Error catcher       | `ExceptionCatcher` interface | Lambda               |
| Filter method       | Protected `shouldLog`        | Public `shouldTrack` |
| Lifecycle callbacks | None                         | Yes                  |
| `@JvmStatic`        | Partial                      | None                 |

`desktopMain`'s `getLinkToCurrentMethod()` returns `null` although the JVM stack-walking code of `androidMain` would work there.

### Tests

- **Logger**: a single `SystemOutLogTest`, JUnit 4, without assertion, under `src/test/java`, outside any KMP source set, so it likely never runs. Coverage is close to zero.
- **Tracker**: six test classes in `commonTest` with `kotlin.test`, covering consent, add and remove, forwarding, attributes and the builder. Coverage is around 50-60 % of `commonMain`. Gaps: `updateUser`, `updateConnectivity`, `logoutUser`, `init`, the exception path, `LogEvent`, the device classes. Tests share the singleton; `OnTrackerRemovedTest` has no `@BeforeTest`, so results depend on order; `TrackerTest` has an assertion-free test with commented-out code; fakes are named `InMemoryTracker` and `FakeUser`, against the `Ram*` convention.
- **Satellite modules**: none.

### Documentation

- KDoc uses Java `{@link}` syntax and contains errors ("LogChild interface", "list of [Tracker]").
- The root `README.md` is minimal; no module has its own README.
- `release_notes.txt` files are stale: `logger-crashlytics` and `tracker-firebase` still describe 2016 releases mentioning Fabric and Toaster.
- The untracked `AGENTS.md` found at audit time described a `LogEntry` type and `log(entry)` signatures that do not exist.

## Consumers

Two consumer projects were surveyed. Neither depends on the libraries yet, so the API can change freely.

| Aspect             | What the consumers have in common                                                          |
|--------------------|--------------------------------------------------------------------------------------------|
| Targets            | Android, `iosArm64`, `iosSimulatorArm64`, `jvm`; one also runs a Ktor server               |
| Toolchain          | Recent AGP with the KMP Android library plugin                                             |
| Logging today      | `println` calls, or nothing on the client; logback on the server                           |
| Tracking today     | None; Firebase already chosen                                                              |
| Repositories       | `google()`, sometimes filtered by group, and `mavenCentral()`                              |
| iOS integration    | One umbrella framework embedded through `embedAndSignAppleFrameworkForXcode`, no CocoaPods |
| Privacy constraint | Some values, such as invitation codes, must never reach a log, an event or a crash report  |

Publishing to Maven Central therefore requires no change to the consumers' repositories.
